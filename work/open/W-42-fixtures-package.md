# W-42 — `@sheetpane/fixtures`: sample workbooks hosts can test with

## At a glance

| step | what we do | what it gives us | state |
|---|---|---|---|
| 1 | Collect the files: showcase (W-32), rules sample (W-33), CSV variants (comma, semicolon, BOM, quoting), edge cases (empty, merged, frozen, hidden sheet) and a large-file generator | hosts test against the files sheetpane is tested with | ⏳ |
| 2 | Expose them: `fixtures.showcase.path`, `.url`, `await .bytes()`, plus a manifest of what each contains | one line to load, and you know what to assert | ⏳ |
| 3 | Add W-30's four app-saved files when they exist | real-world files, not only hand-built ones | ⏳ |

**Arpit, 2026-10-18:** *"Other than codemods. File work item for everything else. Research and then file work items."* — answering the chat list (same session as [W-35](W-35-agent-skills-package.md)) of what helps a consumer beyond skills.

**Model:** Sonnet — packaging and a manifest; the generators exist.

## Goal

Any host, with any test runner, can load a known workbook and know what is in it.

## Definition of done

| DoD | what | state |
|---|---|---|
| 1 · package | `packages/fixtures`, files plus a tiny ESM index; no dependencies | ⏳ |
| 2 · files | showcase.xlsx, showcase.rules.json, csv/ variants, edge/ cases — each generated by a checked-in script where hand-built (never hand-zipped) | ⏳ |
| 3 · manifest | `fixtures.json`: per file — sheets, headers, features exercised, the errors the rules sample should produce | ⏳ |
| 4 · API | `path` (Node), `url` (bundlers, `new URL(…, import.meta.url)`), `bytes()` | ⏳ |
| 5 · real files | W-30's app-saved files with the app and version in the manifest | ⏳ |
| 6 · used | the repo's tests, the demos and [W-41](W-41-testing-package.md) load from here instead of private copies | ⏳ |
| 7 · record | new record SR-FIXTURES; ownership row | ⏳ |

## Blockers

- **Size:** the huge-row case is a generator, not a file.
